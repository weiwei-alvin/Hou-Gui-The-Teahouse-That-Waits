# 候歸茶館 Hou Gui Teahouse｜設計定案 v0.4

狀態：定案（2026-10-28 晚，經使用者逐條確認）。取代 v0.3 與其附註；之後的改動都改這一份。
用途：DEV Hacktoberfest Open-Source AI Challenge Week 4「Ghost in the Machine」。截止 2026-11-01（日）14:59 台灣時間。

## 1. 不變的核心（v0.1 已確認）
- 玩家透過投入，親手改變環境。
- 修復後仍是鬼鎮：陰森、微驚悚、不血腥；鬼保留非人特徵。
- 修復順序與對角色的互動都要影響體驗。
- 固定世界規則＋有記憶的 AI 角色；模型不能否認或改寫已完成的成果。
- 例外（使用者同意）：心結解開那一刻，茶館才轉為暖光；修復過程維持冷色。

## 2. 故事
- 主角回鄉下參加姑婆的喪禮，在遺物裡找到寫著自己名字的信封：一把舊鑰匙，和一封被雨水暈開的信。讀得清的只有「…總得有人回去，把茶館打理好…我的鶴杯…他會認得…」。
- 小鎮空了幾十年。茶館掌櫃是一隻鬼，一直守在門口，等當年和他一起開店、答應會回來的她。
- 主線：一隻鬼、一個心結。玩家要替掌櫃解開心結。
- 門燈亮起後，門口出現的客人就是剛過世、終於回來的姑婆。掌櫃認不出她。
- 對外介紹不暴雷：不提客人身分、心結解法、順序效果。

## 4. 玩法
三項修復，可任選順序，每一下點擊都要讓場景出現可見變化：
1. 門燈：扶正燈柱 → 用木料補好 → 點亮（點亮後客人出現在門口）。
2. 茶具與爐子：撿回茶具 → 修好爐子 → 擺好茶具、生火。
3. 候客區：清走破木箱（底下找到鶴杯）→ 桌椅擺窗邊或火盆旁（兩者同等有效，沒有正解）。

解心結靠動手，不靠對話：
- 找：清木箱時找到鶴杯。
- 認：仔細查看客人，會看到她提著和門燈同款的小燈籠（線索，不是條件）。
- 備：爐子修好後，親手把茶倒進鶴杯。
- 奉：客人入座後，把鶴杯放到她面前。→ 規則判定心結解開。
- 只靠對話永遠解不開（有自動測試證明）。

對話的角色：玩家可自由輸入或用快捷說法，指揮掌櫃接待、請客人稍候、不理會等；掌櫃可以用暗示的方式提起對她的回憶（鶴杯、燈籠），但不會說破客人是誰。

## 5. 客人與結局（全部由規則判定）
| 玩家做了什麼 | 結局 |
|---|---|
| 鶴杯奉給入座的她 | 心結解開 → 暖光 → 由模型自己決定留下（stay_on）或和她一起離開（move_on） |
| 接待了，但沒給她鶴杯，就出去再回來 | 她喝完一般的茶，安靜離開；掌櫃繼續等（unresolved_quiet） |
| 只請她在長凳等，出去再回來 | 她還在等；之後接待、奉杯仍可解開心結 |
| 從頭到尾晾著她，出去再回來 | 她走了；茶館修好但仍冷，掌櫃守在門口（unresolved） |

- 門外長凳是原本就有的臨時等候處，不取代修好的候客區。
- 暫候（長凳）、接待（掌櫃到門邊）、入座（進入候客區）三種位置都看得出差別。

## 6. AI 的職責與邊界
- 模型：本機 Gemma 4（預設 `gemma4:e4b`，延遲不達標改 `e2b`），經 Ollama。
- 模型輸出：台詞、暫時態度、最多兩個事件 id、最多一個行動提案。格式以 JSON schema 約束。
- 只有通過規則驗證的行動才會執行並產生事件；模型不能寫入世界狀態、修改歷史或修復成果。
- 能不能放下由規則決定；放下後要走要留，由模型決定（使用者：「應該是鬼自己的決定，這樣才是真正的自由」）。
- 台詞下的「相關事件」由程式依事件紀錄產生；程式保證事件真實，不保證模型引用得恰當。
- 台詞只表達感受、需求、意圖與對她的舊回憶，不敘述今晚發生的事。這是行為要求，不是程式保證；違規由測試計數，文章如實寫成限制。
- 請求綁定：程式記住請求 ID 與發送時的狀態版本；版本不同 → 整份回應不套用並自動重送；逾時 → 請求失效，之後才到的回應一律不套用；同時最多一個請求。
- 降級與腳本測試模式一律標示「不是模型的回應」；腳本模式做的結局選擇也標示不是模型做的。

## 7. 驗證
- 規則層自動測試（`npm test`）：六種順序 × 兩種擺位、鶴杯謎題、四種結局、只靠對話解不開、過期與逾時政策、Python 測試與遊戲送出的 prompt 逐字相同。
- 瀏覽器自動檢查（腳本模式＋假的 Ollama）：所有流程、降級、手機寬度。
- 模型層（使用者電腦，`tools/keeper_model_test.py`）：延遲、格式、意圖符合度；人工標記台詞違規。另需記錄放下後選擇留下／離開的比例，文章照實寫。
- 真人試玩：至少一人，觀察能否不靠提示找到鶴杯、認出她、完成奉杯。
- 離線宣稱：斷網冷啟動並跑完一局後才寫。
