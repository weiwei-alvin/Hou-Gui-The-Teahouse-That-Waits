# Hou Gui Teahouse 候歸茶館

A tiny ghost-town repair game. You fix a haunted teahouse, one lamp, stove and table at a time. Its keeper is a ghost whose words and choices come from an open-weight model running on your own computer (Gemma 4 through [Ollama](https://ollama.com)).

**The ghost is the model; the machine is the rules.** The keeper can feel, interpret and propose. Only the game's rules can change the world, and only the game's event log decides what happened.

Built for the DEV Hacktoberfest Open-Source AI Challenge, Week 4: *Ghost in the Machine*. The project and repository were created during the entry period (from 2026-10-26 09:00 PDT). Any commit after the deadline (2026-10-31 23:59 PDT) will be listed at the bottom of this file.

## The story, without spoilers

You go back to the village for your great-aunt's funeral, and find an envelope with your name on it: an old key, and a letter the rain has half washed away. The town on the map has been empty for decades. Someone behind the teahouse counter is still waiting, and not for you.

Whether the keeper can let go is decided by the game's rules, from what you actually did. What the keeper does once free is left to the model: it may stay, or it may move on. Endings can differ between runs for that reason, and the model-layer test records how often each happens instead of promising one outcome.

## How the keeper is kept honest

- **One way to change the world.** The model returns JSON with a line, an attitude, up to two event ids, and at most one action from a fixed list. The rules check the action's preconditions and, if they pass, execute it and record an event. The model cannot write state, history or repairs.
- **Facts come from the log.** Under each line, "Related events" is generated by the game from the event ids the model chose. The game guarantees those events are real; it cannot guarantee the model chose the right ones.
- **Replies are bound to requests.** The game remembers the state version each request was sent at. If anything changed before the reply arrives, the whole reply is dropped and the keeper is asked again with the new state. Only one request is in flight; anything that happens meanwhile is merged into the next one.
- **Timeouts are final.** After the timeout (10 s by default) the request is dead, and a late reply is never applied. The keeper falls silent, the screen says so, and your repairs are kept.
- **Fallbacks are labeled.** Silence after a failure, and replies in scripted test mode, are always marked as not coming from the model.

**What is not solved:** the keeper's free-text line can still state a guess as if it had happened. The prompt asks it not to, but code cannot reliably check meaning. The model-layer test counts these cases by hand instead of claiming they never occur.

## Run it

You need [Ollama](https://ollama.com/download), Python 3 (only to serve the files) and a modern browser.

```sh
ollama pull gemma4:e4b        # or gemma4:e2b on slower machines
python -m http.server 8000    # from this folder
```

Open <http://localhost:8000>. Open it through `http://localhost`, not by double-clicking the file.

- **No model, or just looking around:** <http://localhost:8000/?mode=scripted> runs a scripted test mode. Its replies are fixed rules and are labeled as such.
- **Settings** (model, Ollama address, timeout) and a request log are under "Settings and request log". You can download the session log as JSON there.
- **If the page cannot reach Ollama:** make sure Ollama is running. If it still fails, set the environment variable `OLLAMA_ORIGINS` to `http://localhost:8000` and restart Ollama.

## Tests

```sh
npm test                                   # Node 20+, no dependencies
```

- `test/rules.test.mjs`: all six repair orders × both seating spots complete; out-of-order steps, repeated repairs and illegal actions are refused; keeper actions never touch repairs or history; stages only move forward.
- `test/keeper.test.mjs`: stale replies are dropped whole and resent; late replies after a timeout change nothing; one request in flight; bad formats, unknown event ids and refused actions degrade without changing the world.
- `test/parity.test.mjs`: the Python model-layer test sends the model exactly the prompt the game sends.

Browser check (needs Playwright with Chromium; uses a fake Ollama, never a real model):

```sh
python test/e2e/mock_ollama.py 18560 &
python -m http.server 8000 &
node test/e2e/game.e2e.cjs http://localhost:8000 http://127.0.0.1:18560
```

Model-layer test against your real local model (latency, format, rule checks, intent match; writes `keeper_test_results.json` with fields for hand labels):

```sh
python tools/keeper_model_test.py --model gemma4:e4b --runs 3
```

## Files

- `src/rules.js`: world state, repairs, guest, keeper actions and their preconditions, event log. No DOM, no model.
- `src/keeper.js`: prompt building, request binding, timeout and stale policy, reply validation, Ollama and scripted transports.
- `src/keeper_prompt.json`: the prompt, attitudes and actions. Shared by the game and the model-layer test.
- `src/main.js`, `src/style.css`, `index.html`: the page and the scene.
- `docs/design-v0.4.zh-TW.md`: the design document (Traditional Chinese). Contains spoilers.
